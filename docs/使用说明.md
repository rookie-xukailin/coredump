# bmccore 使用说明

BMC coredump 离线分析工具（ARM32 / ARM64 / RISC-V）。
把设备上的 core 包拷到编译服务器，一条命令得到带可信度标注的定位报告。

## 1. 一次性配置

以下命令在 `bmccore.py` 所在目录（技能根目录 `swrd-skill-coredump-analyze/`）执行：

```bash
cp bmccore.toml.example bmccore.toml   # 放在 core 文件所在目录或其上层
vi bmccore.toml                        # 填产物目录/源码树/sysroot/工具链
```

要求：
- **产物目录**（`artifact_dir`）：堆未 strip 的编译产物。工具按 build-id 自动配对，
  目录里堆多版本产物也没关系。**务必保留每个发布固件对应的未 strip 产物**，
  版本对不上时工具会明确报 mismatch，而不是猜。
- **工具链**：不配则自动探测 `aarch64-linux-gnu-gdb` 等常见前缀，找不到时用
  `gdb-multiarch`。没有 gdb 也能跑：GDB 精确回溯跳过，栈扫描兜底照常工作。
- **Python 3.8+**（基线 3.8；vendored pyelftools 固定 0.31.x 以兼容 3.8，升级依赖前必须在真实 3.8 上全量回归）

## 2. 日常使用

```bash
# 快速摘要（不解符号，秒出）
python3 bmccore.py info 1_core-2078599821-remotexdp-6759.tar.gz

# 全量分析（在 core 所在目录执行，自动读 bmccore.toml）
python3 bmccore.py analyze 1_core-2078599821-remotexdp-6759.tar.gz

# 附加串口日志（强烈建议：glibc 堆报错只打印在 stderr，core 里没有）
python3 bmccore.py analyze core包.tar.gz --console-log console.log
```

输出：`bmccore_report/<输入名>_report.md`（人读）与 `.json`（机读）。

## 3. 报告怎么读

- **定位结论**节是最终答案，每条带可信度：
  - `确认` = 有硬证据（信号/siginfo/console 明确报错/指令级验证通过的栈帧）
  - `疑似` = 强启发式推断（栈扫描帧、堆损坏点归属），会注明依据
- **符号配对**节：`matched` = build-id 精确对上；`byname` = 只对上文件名（降可信）；
  `missing` = 产物目录里没有这个 so（检查产物是否齐全/固件版本）。
- **栈扫描**节：`确认` 帧满足"值落在代码段 + 前一条指令经反汇编判定是 call"；
  `未验证` 帧只有代码区间命中，仅供参考。
- **堆取证**节：chunk 头损坏点 + **前一个 chunk 是重点嫌疑**（越界写穿模式）+
  谁持有指向受害区的指针（引用者往往就是肇事数据结构的邻居）+ 内容指纹
  （被踩区出现可读字符串时，拿去源码 grep 常直接锁定模块）。

## 4. 三类疑难场景的对应技能

| 症状 | 工具行为 |
|---|---|
| GDB 回溯全是 `??` | 符号自动配对（build-id）+ 重新挂载；配不上时报告明说 |
| 栈被踩坏/栈溢出 | 栈扫描兜底（指令级 call 验证），SP 出界/贴底直判栈溢出 |
| 内存被踩 | glibc chunk 链走查定位损坏点，前块嫌疑分析，引用搜索，内容指纹 |

## 5. 常见问题

- **报告说"模块 missing"**：产物目录里没有该 so 的未 strip 版本。把对应固件
  版本的完整产物放进 `artifact_dir`，或用 `--module libfoo.so=/路径` 手动指定。
- **回溯帧的函数对但行号没有**：产物是 strip 的或没编 `-g`。行号来自 DWARF，
  函数名来自 symtab，两者要求不同。
- **堆取证显示"core 中无堆数据"**：设备端 `coredump_filter` 裁掉了匿名段，
  或进程本身没堆。检查 `/proc/<pid>/coredump_filter`（默认 0x33 即可）。
- **zstd 压缩包**：python 标准库不带 zstd，先 `zstd -d` 再喂。

## 7. 目录结构

```
swrd-skill-coredump-analyze/      自包含技能包（可整目录拷入各 Agent 技能目录）
├── SKILL.md           技能入口（Agent 技能定义）
├── bmccore.py         CLI 入口（实现在 bmccore/cli.py）
├── bmccore/           工具包：intake/corefile/modules/arch/symbols/scan/heap/...
├── open/pyelftools/   直接引用的开源项目（vendored）
├── scripts/           技能辅助脚本（报告 JSON 转结构化数据）
└── bmccore.toml.example
tests/                 合成 core 生成器 + 全部单测（仓库开发资产）
tools/                 测试 case 生成/校验脚本（仓库开发资产）
docs/                  使用说明
```
